How an LLM writes an answer, and where it gets stuck

An LLM is a model that reads text and writes the text that comes next, one token at a time. It picks each next token by looking at probabilities, and those probabilities come from its parameters and from the text you give it.

The lecture opens with a question: Which office hour this week is least crowded? The course's TAs, senior students who help with teaching, hold office hours twice a week: Tuesday 4pm and Thursday 9am. Office hours are fixed times when any student can drop in and ask questions. Ask an LLM on its own, and it answers with confidence: Try the Wednesday afternoon session - midweek hours are usually quietest.

The course keeps a queue log, a record of how many students were waiting in line at each office hour. Over the last 3 weeks, Tuesday 4pm averaged 14 students and Thursday 9am only 3. So the right answer is Thursday 9am, and there is no office hour on Wednesday at all. The LLM never saw this log, yet it did not hesitate for a moment. This lesson explains why.

1Tokens: the model reads pieces of text

A token is a small piece of text: sometimes a whole word, sometimes part of a word, sometimes a punctuation mark. An LLM reads text by splitting it into tokens, and it writes its answer in tokens too.

Tokens are needed because a computer can only calculate with numbers. The model has a fixed list of tokens, and each token in it has an ID number. This list is called the vocabulary, and the program that splits text into its tokens is called the tokenizer.

A common word is often a single token, while a rarer word breaks into a few pieces. For example, Office hours are crowded on Tuesday has 6 words but 7 tokens: my split

Office hours are crowded on Tuesday

Here crowded broke into two tokens, crowd and ed. In the same way, if the vocabulary has no entry for a misspelling like Wednesdayy, the tokenizer still splits it into Wednesday and y. The real split depends on each model's own tokenizer.

Since the model reads and writes only tokens, this lecture measures every length in tokens, not in words.

2Next-token prediction: one token per step

While writing an answer, an LLM gives every token a probability at each step, then picks one token and adds it to the text. Then it repeats the same thing on the new text. This loop is called next-token prediction, and the whole answer comes out of it.

A probability is a number between 0 and 1 that gives the chance of something happening: 0 means never, and 1 means certain. For example, if 5 of the last 20 lectures had a quiz, the probability of a quiz in the next one is 5 ÷ 20 = 0.25. The probability of no quiz is 15 ÷ 20 = 0.75, and the probabilities of all the options always add up to 1.

3Parameters and training: where the model's knowledge lives

Parameters are the numbers inside a model. The input tokens are combined with these numbers by a fixed calculation, and that calculation produces the probability of every next token. Another name for parameters is weights, and there are a great many of them. The T5-11B model on Stanford's slides, for example, has about 11 billion parameters. from the paper

The values of these parameters are set by training. At first the parameters are random. Then the model reads a large amount of text, and at every position training checks what probability the model gave to the real next token. Then it nudges the parameters a little so that this probability goes up.

Here is one step. The training text contains the line Office hours are on Thursday. After reading Office hours are on, the model gives the next token Thursday a probability of 0.10. Training changes the parameters slightly, and now the same text gives Thursday 0.12. my example The total stays at 1, so all the other tokens together dropped from 0.90 to 0.88.

So whatever the model “knows” is spread across the values of its parameters, not stored in a separate file or database. Knowledge held this way is called parametric knowledge. Training stops on some date, and after that the parameters do not change. That date is called the knowledge cutoff.

The queue log is this course's own data, so it never went into any model's training. Its 14 and 3 are not in any parameter. This shows the two problems with parametric knowledge:

  • New facts do not get in. To add something from after the knowledge cutoff, or your private data, the model has to be trained again.
  • The model cannot name a source. The knowledge is mixed into billions of numbers, so the model cannot tell which document a fact came from.

4The prompt and the context window

The prompt is the text you give the model right now: the question, instructions, and any document that comes with them. At every step, next-token prediction looks at all the text so far, and that includes the prompt. So the prompt's text can change every probability, while the parameters stay the same.

Now put the queue log line in the prompt before the question, the line that says 14 for Tuesday 4pm and 3 for Thursday 9am.

Think first: The parameters are the same, and only the prompt changed. Will Thursday's 0.21 and Wednesday's 0.34 go up or down? Make a guess, then switch on the box below.

The parameters stay the same. Only the prompt changes. my numbers

With the log added, Thursday's probability goes from 0.21 to 0.81, and Wednesday's from 0.34 to 0.05, while the parameters stay the same. Put information that is not in the parameters into the prompt, and the model uses it. The whole lecture is built on this.

The prompt has a limit too. The model can read only a fixed number of tokens at once, and this limit is called the context window. Both the prompt and the answer the model writes count toward it. For example, if the window is 8,000 tokens and the prompt is 7,500, only 500 tokens are left for the answer.

All of a course's documents together can be far larger than this window. So for every question you have to choose which pieces go into the prompt, and lesson 2 starts from that choice.

Think first

Show the answer

That leaves 8,000 − 300 − 700 = 7,000 tokens for passages, and 7,000 ÷ 500 = 14 passages.

5Hallucination: a confident answer without data

A hallucination is an answer that reads well and sounds confident, but is wrong or does not rest on any source. The Wednesday afternoon answer is one, and its cause comes from putting the last three steps together.

The queue log was not in the parameters, because it never went into training (step 3). It was not in the prompt either (step 4). Even so, next-token prediction picks some token at every step, and the most common token was Wednesday (step 2).

Next-token prediction has no step that stops when the data is missing. So a wrong answer is written with the same confidence as a right one, and the reader cannot tell them apart.

The right half of the slide shows retrieval, which means finding the right text when the question arrives and putting it into the prompt. There the answer's 3 comes straight from the log line, so a reader can check it. Lesson 2 starts from here.

6The slide's notation: p(y | x, z), θ, and the probability of a whole answer

Stanford's slides call the LLM a generator and describe its job in one line:

A generator p(y|x, z) that writes the answer one token at a time, given the query x and a retrieved passage z.

This line is the next-token prediction of step 2, written in symbols. In this step you read every symbol in it with your own numbers.

The text after the “|”: p(y | x) and p(y | x, z)

Before the symbols, take two numbers from step 4. After the text The least crowded office hour this week is, Thursday got 0.21, and with the queue log line placed before it, 0.81. The token was the same, and only the text before it changed. The notation records exactly this difference:

SymbolMeaningIn our example
xThe query, the text the model receivesThe least crowded office hour this week is

yThe answer, or one of its tokensThursday
p(y | x)The probability of y when only x is given0.21
p(y | x, z)The probability of y when both x and z are given0.81

The vertical bar “|” is read “given”. After it comes the text the model already has, and the comma means “and”. Lesson 4 explains this fully under the name . For now it is enough that changing the text after the “|” changes the probability of the same token.

θ: the generator's parameters

On the slide the generator's full name is pθ. θ (theta) is the name for the generator's parameters, all the numbers from step 3. Writing θ underneath says that these probabilities come from those parameters. The retriever's parameters are called η (eta), and they come in lesson 5.

The training step from step 3 looks like this in the notation: pθ(Thursday | Office hours are on) was 0.10, and after θ changed slightly it became 0.12. There the text stayed the same and θ changed. In step 4 it was the other way round: θ stayed the same, and the text after the “|” changed.

One token at a time: the probability of a whole answer

The generator writes the answer one token at a time, so the probability of the whole answer is built from the probability of each token. Counting shows this most clearly. Suppose the model writes the same answer 1,000 times, choosing at random each time with the widget's probabilities: my numbers

  1. At the first step, Wednesday comes up about 1,000 × 0.34 = 340 times.
  2. In 46% of those 340, the next token is afternoon: 340 × 0.46 = 156.4, so about 156 times.
  3. In 71% of those, a full stop follows: 156.4 × 0.71 = 111.0, so about 111 times.

111 times out of 1,000 means the whole answer Wednesday afternoon. has probability 0.111. That is the product of the three probabilities: 0.34 × 0.46 × 0.71 = 0.111. Each step keeps a share of the cases left by the step before, which is why the probabilities multiply. The formula writes the same product like this:

p(y | x) = p(y1 | x) × p(y2 | x, y1) × p(y3 | x, y1, y2)

Here y1 = Wednesday (0.34), y2 = afternoon (0.46) and y3 = the full stop (0.71). After the “|” of each token come the question and all the tokens before it, because next-token prediction looks at all the text so far at every step. The RAG paper writes each token's probability as pθ(yi | x, z, y1:i−1), where y1:i−1 means tokens 1 to i − 1. from the paper

Think first

Take the widget's other answer, Thursday morning., whose tokens have probabilities 0.21, 0.31 and 0.71. What is the probability of this whole answer, and how many times more often does Wednesday afternoon. come up?

Show the answer

0.21 × 0.31 = 0.0651, and 0.0651 × 0.71 = 0.046, so about 46 times in 1,000. Wednesday afternoon comes up 0.111 ÷ 0.046 = 2.4 times as often.

The same product shows one more thing. Every probability is below 1, so every extra token lowers the probability of the whole answer. Even this widget's most common answer sits at only 0.111, which means that about 889 times in 1,000 the model writes something else.

Greedy decoding and sampling

There are two common ways to pick a token, and both appeared in step 2. Taking the highest-probability token at every step is called greedy decoding. The widget's “Pick the highest” does this, and its answer is always Wednesday afternoon. Choosing at random according to the probabilities is called sampling, and the 1,000-run count above was sampling.

With sampling, the first token can change from run to run. Run it 100 times and you get Wednesday about 34 times, Thursday 21, Tuesday 18, Friday 15 and Monday 12. So sampling sometimes writes the right Thursday too, but only by luck, as in the question in step 2.

For question answering, papers often use greedy decoding. The T5 paper in step 7 picks the most likely token at each step, and the RAG paper also uses greedy decoding for question answering. from the paper

7Closed-book QA: how many answers come from parameters alone

In closed-book question answering the model gets only the question and no document, so it writes the answer from its parameters alone. That is exactly what the LLM on its own did at the start of the lesson. In the open-book setting the system first searches documents and then writes the answer. Stanford's RAG Performance slide compares models.

The slide's closed-book rows come from a 2020 paper by Roberts and colleagues. They taught Google's T5, a model that reads text and writes text, to answer questions given only the question, with no documents at all. from the paper From here on this paper is called the T5 paper.

Exact Match: did the answer match word for word

The numbers in these tables are scores: the percentage of questions where the model's answer matches the correct answer exactly. Before matching, both are lowercased, and a, an, the, punctuation and extra spaces are removed. from the paper For example, if the correct answer is Thursday 9am, then thursday 9am. matches. But Thursday 9 am does not, because it has a space between 9 and am.

The four columns of the slide's table are four datasets. NQ is Natural Questions, real questions people typed into Google search. TQA is TriviaQA, questions from quiz websites. WQ is WebQuestions and CT is CuratedTrec, two smaller question-answer datasets. from the paper

What changes when the parameters grow

T5 comes in four sizes, and the paper trained all four in the same way to answer questions. Below are the numbers on TriviaQA's Wikipedia test set: from the paper

From Base to 11B the parameters grow 11,000 ÷ 220 = 50 times, and the score rises from 29.1 to 50.1, a gain of 21.0 points. Each larger size answers more questions exactly right, so a bigger model holds more knowledge in its parameters. This TriviaQA column is used because its 50.1 and 60.5 are the same numbers as on Stanford's slide. For NQ, the current version of this paper gives T5-11B 32.6 while the slide says 34.5, so for NQ use the slide's number.

The SSM in the last row, salient span masking, is an extra round of training. In it the model reads Wikipedia sentences with blanks where names and dates were, and has to fill in the blanks. T5 ran this round for 100,000 extra steps, and the TriviaQA score went from 50.1 to 60.5. from the paper This round is part of , the large training on general text that comes before the model is taught to answer questions.

Fewer parameters, with documents

Now look at the NQ column of the slide's table. In the closed-book rows, T5-11B is at 34.5, and 36.6 with SSM. In the open-book rows, RAG-Seq. is at 44.5. Out of 1,000 questions, that is 345 against 445 exactly right answers, so the system with documents gets 100 more questions right.

RAG's generator is a model called , with about 400 million parameters, and the whole of RAG has about 626 million. T5-11B has 11 billion, which is 11,000 ÷ 626 = 17.6 times as many. The RAG paper also notes that T5-Large, with 770 million parameters, scores 28.9 on NQ. from the paper

So with documents at hand, a system with 17.6 times fewer parameters is still 10 points ahead on NQ. The RAG paper draws the same conclusion: a system that combines parameters with documents needs far fewer parameters to answer questions well. The gain comes from step 4, because the text with the answer reaches the prompt.

8The papers' experiments: measuring hallucination and the knowledge cutoff

Steps 3 and 5 named three weaknesses of parametric knowledge: new facts do not get in, there is no source, and an answer comes out even without the data. The RAG paper opens with the same three. Such models cannot easily expand or revise their memory, cannot show why they predicted something, and can hallucinate. from the paper The three experiments in this step put numbers on them.

150 answers Exact Match called wrong, checked by hand

The T5 paper checked by hand 150 answers on NQ that Exact Match had marked wrong. They fell into four groups: from the paper

The confetti answer reads just as well as a correct one, and that is a hallucination. The last row ties to the knowledge cutoff, because its answer changes over time while the parameters stay fixed at training time.

At the end of the paper the authors themselves name three points. The model spreads knowledge across its parameters in a way nobody can explain. When it is unsure, it makes up realistic-looking answers. And after training there is no way to add or remove a specific fact. from the paper

Jeopardy questions: people judged factuality

In the RAG paper, people checked hallucination directly. Jeopardy is a quiz format where the answer comes first, and you write a question that has it as its answer. For the answer The World Cup, for example: In 1986 Mexico scored as the first country to host this international sports competition twice. from the paper

Two models wrote such questions. BART is a generator on its own, writing only from its parameters. RAG has the same BART, but its prompt also holds Wikipedia passages. For the same answer RAG wrote It’s the only U.S. state named for a U.S. president. from the paper

In another task the model had to write a one-sentence answer to define middle ear. There BART wrote that the middle ear is the part of the ear between the middle ear and the nose, which is wrong. RAG wrote The middle ear includes the tympanic cavity and the three ossicles. from the paper

New knowledge by swapping the documents: index hot-swapping

The first problem in step 3 was that adding a new fact needs training again. RAG keeps its documents in an , a list of passages organised so the retriever can search it fast. The RAG paper built two indexes from Wikipedia, one from December 2016 and one from December 2018. from the paper

The paper then listed 82 world leaders who changed between those two dates, and asked the model questions like Who is the President of Peru?. The model's parameters were the same in all four cases, and only the index changed: from the paper

Index ↓ / leaders of which year →20162018
December 2016 index70%4%
December 2018 index12%68%

With the index from the right year, 68% to 70% of the answers are correct, and with the wrong year only 4% to 12%. So swapping the documents changed what the model knows, and it took no training. Replacing the index like this is called index hot-swapping. Lesson 2 calls this route : knowledge kept outside the parameters, in documents.

Think first

The course moved the Thursday office hour from 9am to 10am. What has to change to get this right in a system with an LLM alone, and in a system with documents?

Show the answer

For the LLM alone, the parameters have to change, which means training again. In the system with documents, changing the office hours passage is enough, because on the next question the retriever brings the new passage into the prompt. The paper's 2016 and 2018 experiment shows exactly this.

3 points from this lesson

  1. An LLM writes one token at a time. The probability of a whole answer is the product of its tokens' probabilities, for example 0.34 × 0.46 × 0.71 = 0.111.
  2. Knowledge comes from two places: the parameters and the prompt. T5-11B, with parameters alone, scores 34.5 on NQ, while RAG with documents scores 44.5 with 17.6 times fewer parameters.
  3. A probability says what is common, not what is true. People judged RAG's questions more factual 6 times as often as BART's alone, and swapping the index brought in new knowledge without training.

New terms in this lesson

LLM
Large language model: a model that reads text and writes what comes next, one token at a time. For example, the model that wrote Wednesday afternoon.
Token
A small piece of text: a word, part of a word, or punctuation. The model reads and writes these. For example, crowded is two tokens, crowd and ed.
Vocabulary
The model's fixed list of tokens, each with an ID number. For example, it contains Wednesday but not Wednesdayy.
Tokenizer
The program that splits text into the vocabulary's tokens. For example, it splits Wednesdayy into Wednesday and y.
Probability
A number between 0 and 1 that gives the chance of something. The options always add up to 1. For example, a quiz in 5 of 20 lectures gives 5 ÷ 20 = 0.25.
Next-token prediction
Looking at the text so far, giving every token a probability, picking one, adding it, and repeating. For example, Wednesday, then afternoon, then a full stop.
Parameters (weights)
The numbers inside a model that produce the probability of every next token. For example, T5-11B has about 11 billion parameters.
Training
Changing the parameters little by little so that the real next token in the text gets a higher probability. For example, Thursday after Office hours are on goes from 0.10 to 0.12.
Parametric knowledge
Knowledge spread across the parameters. The model cannot name its source, and a new fact needs training again.
Knowledge cutoff
The date on which training stopped. Later events, and your private data, are not in the model. For example, with a March 2026 cutoff, an October 2026 announcement is not in the model.
Prompt
The text you give the model right now: the question, instructions, and accompanying documents. For example, the queue log line that lifted Thursday from 0.21 to 0.81.
Context window
The most tokens a model can read at once. Both the prompt and the answer count. For example, an 8,000-token window with a 7,500-token prompt leaves 500 for the answer.
Hallucination
A confident answer that is wrong or has no source. For example, Wednesday afternoon, written without seeing the log.
Greedy decoding and sampling
Greedy decoding takes the highest-probability token at every step, and sampling chooses at random according to the probabilities. For example, greedy always writes Wednesday afternoon, while sampling starts with Thursday about 21 times in 100.
Salient span masking (SSM)
An extra round of pretraining in which the model fills in blanked-out names and dates in Wikipedia sentences. For example, it lifted T5-11B's TriviaQA score from 50.1 to 60.5.
BART
A model that reads text and writes text, with about 400 million parameters. It is RAG's generator. For example, in the Jeopardy test BART on its own was judged more factual in only 7.1% of pairs.
Index hot-swapping
Replacing the document index without touching the parameters, so that the model's knowledge changes. For example, the 2018 index answered 68% of questions about 2018 leaders correctly, and the 2016 index only 4%.
