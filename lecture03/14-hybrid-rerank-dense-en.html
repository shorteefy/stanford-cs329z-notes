1BM25 and dense retrieval miss different passages

BM25 and a dense retriever fail on different kinds of text, so on the same query they leave out different correct passages. BM25 counts the words a query and a passage share, while a dense retriever such as compares their .

BM25 fails when a passage says the same thing in other words, which is called a paraphrase. For example, the query says upload failed and the passage says upload keeps failing. To BM25, failing and failed are different words, so the only match it finds is upload.

A dense retriever fails when something has to match exactly, such as an error code or an order ID. Text like this is called a literal. Lesson 3 showed that passages with E-4012 and E-4021 can get almost the same embedding. To BM25, 4012 is a rare word with a high IDF, so it finds the right passage.

3Reciprocal rank fusion: merging ranks instead of scores

The scores have different scales, but ranks have the same scale in every retriever: first, second, third. Reciprocal rank fusion, or RRF, turns a passage's rank in each list into 1 ÷ (60 + rank), and adds these numbers over all lists. The passages are then ordered by this sum.

E1 is at rank 1 in BM25's list, so it gets 1 ÷ (60 + 1) = 1 ÷ 61 = 0.01639, about 0.0164. In the dense list it is at rank 2, so it gets 1 ÷ 62 = 0.01613. E1's RRF is the sum: 0.01639 + 0.01613 = 0.03252.

The new order is E1, E2, E3. Both correct passages moved to the top, and E3 dropped to the bottom, because it was not first in any list.

The three sums sit close together, and the reason is how a fraction behaves. When the bottom of 1 ÷ (60 + rank) grows, the fraction shrinks. But going from 61 to 62 makes the bottom only 1.6% bigger, so the fraction also shrinks by only about 1.6%. That is why RRF numbers stay close together, and only their order matters.

Stanford's slide writes the same arithmetic as a formula:

RRF(d) = ∑r ∈ R 1k + rankr(d),   k = 60
d
A passage, such as E1.
R
The set of retrievers, here {BM25, dense}. The r ∈ R under the means: add over every retriever r in R.
rankr(d)
The rank of d in retriever r's list. For E1, 1 in BM25 and 2 in dense. A list that does not contain d adds nothing.
k
A fixed number, 60. It is not the k of top-k.

What k = 60 does

k = 60 shrinks the gap between rank 1 and rank 2, so rank 1 in a single list cannot decide the result on its own. With k = 0, rank 1 would get 1 and rank 2 would get 0.5, half as much. With k = 60, they get 0.01639 and 0.01613.

Suppose passage A is only in BM25's list, at rank 1, and passage B is at rank 3 in both lists: my example

  • With k = 0, A gets 1 ÷ 1 = 1, and B gets 1 ÷ 3 + 1 ÷ 3 = 0.667. A wins.
  • With k = 60, A gets 1 ÷ 61 = 0.0164, and B gets 1 ÷ 63 + 1 ÷ 63 = 0.0317. B wins.

So with k = 60, the winner is the passage that both retrievers place near the top.

4Cross-encoder: reading the query and the passage together

E1 and E2 are at the top of the RRF list only because the two retrievers agreed on them. Neither retriever read the query and the passage together. In a , a passage's vector is made before any question arrives, and the two meet only at the final dot product.

A cross-encoder joins the query and the passage into one text, feeds it to one model, and gets a single score for that pair. The model is usually an encoder such as .

Attention: each token updates its vector from the other tokens

An encoder makes a vector for every and then updates it many times. In attention, each token takes a weighted average of the other tokens' vectors and uses it as its new vector. In a weighted average you multiply each vector by its weight and add them up, and the weights add up to 1.

In a cross-encoder, the query's tokens can also look at the passage's tokens, which Stanford's slide calls full attention across both. Below, every vector has 2 numbers: the first says how much the token leans toward counted data, and the second how much it leans toward opinion. my numbers

The query token crowded starts as [0.5, 0.5]. When the query is joined with the queue log, crowded gives weight 0.6 to the queue log's averaged [1.0, 0.0] and 0.4 to itself:

  1. First number: 0.6 × 1.0 + 0.4 × 0.5 = 0.6 + 0.2 = 0.8.
  2. Second number: 0.6 × 0.0 + 0.4 × 0.5 = 0 + 0.2 = 0.2.

With the forum post, the same 0.6 goes to usually [0.0, 1.0], and crowded becomes [0.2, 0.8]. So the same query token gets a different vector with every passage. In a bi-encoder, attention runs only inside the query, so crowded keeps one vector for every passage.

At the end, the model gathers the whole pair into one vector and turns it into a score. The reranker in lesson 6 gave the queue log 0.92, the office hours page 0.41 and the forum post 0.35 on the least-crowded question. The retriever had given the queue log and the forum post the same 2. my scores from lesson 6

The price: nothing can be built in advance

Every vector in a cross-encoder depends on the query, so nothing about a passage can be computed before the question arrives. On every query it has to run the whole model once for every passage, while a bi-encoder ran the model once per query.

According to Stanford's slide, a cross-encoder built on BERT-base takes 10,700 ms for 1,000 passages, which is 10.7 ms per passage. BERT-base is the smaller version of BERT. For the 60,000 passages of the company in lesson 2, one query would take 60,000 × 10.7 ms = 642 seconds, about 11 minutes.

6The maths of RRF: how k shrinks the gap between ranks

All of RRF's behaviour comes from one fraction: 1 ÷ (k + rank). Step 3 used k = 60. The table below shows how the same fraction changes for different k: my arithmetic

With k = 0, rank 1 is twice rank 2 and a hundred times rank 100. With k = 60, rank 1 is only 1.016 times rank 2, and 2.6 times rank 100. The reason is that with k = 60 the bottom of the fraction already holds 60. Adding 1 to the rank then takes the bottom from 61 to 62, a change of 1.6%, while with k = 0 the same step takes 1 to 2, a change of 100%.

Rank r in both lists against rank 1 in one list

Now look at A and B from step 3 for any k and r. A is at rank 1 in one list only, so it gets 1 ÷ (k + 1). B is at rank r in both lists, so it gets 2 ÷ (k + r).

There is a simple rule for comparing two positive fractions: a ÷ b is bigger than c ÷ d exactly when a × d is bigger than c × b. For example, 2 ÷ 3 is bigger than 1 ÷ 2, because 2 × 2 = 4 and 1 × 3 = 3. The same rule gives B's condition in three steps:

  1. 2 ÷ (k + r) is bigger than 1 ÷ (k + 1) exactly when 2 × (k + 1) is bigger than 1 × (k + r).
  2. That is, when 2k + 2 is bigger than k + r.
  3. Subtract k from both sides: when k + 2 is bigger than r.

B stays ahead as long as r is smaller than k + 2. With k = 60, B stays ahead up to rank 61. Check: 2 ÷ 121 = 0.016529, which is bigger than 1 ÷ 61 = 0.016393. At r = 62 the two are tied, because 2 ÷ 122 = 1 ÷ 61. With k = 0, B is ahead only at r = 1.

So k decides how deep the agreement between the two retrievers counts. With k = 60, agreement anywhere inside the top 61 outweighs rank 1 in a single list. The widget in step 3 shows the same rule: it keeps B ahead up to r = k + 1.

k is a hyperparameter, and the RRF paper's experiment

Training does not learn k. Someone has to choose it in advance. Lesson 11 called such a number a , like BM25's k1 and b, which the DPR paper set to 0.9 and 0.4.

k = 60 comes from the 2009 paper by Cormack, Clarke and Büttcher that introduced RRF. According to the paper, k = 60 was fixed in a small early experiment and never changed afterwards. In that experiment the paper fused the lists of 30 search systems and measured the result for each k with MAP. from the paper

MAP, or mean average precision, is a number between 0 and 1 for the quality of a ranking, and the bigger it is, the better the ranking. It averages the at the rank of each correct document. In lesson 6, precision was the share of returned passages that are right, such as 0.5 when 1 of 2 is right.

The paper also explains the reasoning behind k. Top ranks matter more, but the effect of lower ranks should not vanish, as it would with an exponential formula. With a score of 1 ÷ 2rank, for example, rank 10 would get 1 ÷ 1,024, about 0.001. In RRF with k = 60, rank 10 gets 87% of what rank 1 gets. According to the paper, k also damps the high ranking that a single outlier system gives, which is exactly what happened with A and B. from the paper

7Putting scores on one scale: min-max, and the DPR paper's sum

In step 2 the plain sum of scores failed because the two scores had different scales. RRF dropped the scores. The other route is to bring both scores onto one scale first, and then add them.

Min-max normalisation maps each list's scores onto 0 to 1: the smallest score becomes 0, the largest becomes 1, and the rest fall in between in proportion. The formula is (x − min) ÷ (max − min). In BM25's list the min is 1.0 and the max is 7.2, so E3's 3.1 becomes (3.1 − 1.0) ÷ (7.2 − 1.0) = 2.1 ÷ 6.2 = 0.339. For the cosines the min is 0.75 and the max is 0.82, so E1's 0.79 becomes 0.04 ÷ 0.07 = 0.571. my scores from step 2

The weakness of min-max: the result depends on the list's min and max

Every min-max score depends on the list's min and max, and those depend on which passages made it into the list. Suppose a fourth, weak passage E4 with cosine 0.60 also enters the dense list. Now the cosine min is 0.60, and the spread is 0.82 − 0.60 = 0.22: my example

  1. E1: (0.79 − 0.60) ÷ 0.22 = 0.19 ÷ 0.22 = 0.864, and the sum is 1 + 0.864 = 1.864.
  2. E3: (0.75 − 0.60) ÷ 0.22 = 0.15 ÷ 0.22 = 0.682, and the sum is 0.339 + 0.682 = 1.021.
  3. E2: (0.82 − 0.60) ÷ 0.22 = 1, and the sum is 0 + 1 = 1.000.

The wrong E3 is now above the correct E2, although the scores of E1, E2 and E3 did not change at all. One low passage joining the list was enough to flip the order. In RRF, E4 would enter the dense list at rank 4, the ranks of E1, E2 and E3 would stay the same, and so would their RRF values.

The DPR paper's BM25 + DPR: a sum of scores with λ

In the dense version of lesson 12, the DPR paper's table had a column called BM25 + DPR. The paper builds this column by adding scores, not with RRF. It takes the top 2,000 passages from BM25 and from DPR, and sorts all passages from both lists again with this score: from the paper

BM25(q, p) + λ · sim(q, p),   λ = 1.1

Here sim(q, p) is DPR's dot-product score, and λ (lambda) is a number that multiplies it. The paper chose λ = 1.1 by checking accuracy on the dev set, the questions researchers use to check their decisions. So this is step 2's multiplying by a number, and that number had to be chosen by looking at data.

The right λ depends on the scale of the scores. On our cosines, λ = 1.1 changes nothing: E1 gets 7.2 + 1.1 × 0.79 = 8.069, E3 gets 3.925, E2 gets 1.902, and the order is BM25's again. DPR's sim is a dot product, not a cosine, and it has no upper limit.

8The cross-encoder from inside: attention weights, the score and training

Attention weights come from a softmax

In step 4, crowded gave weight 0.6 to averaged and 0.4 to itself. The model works these weights out itself. For every pair of tokens it first computes a score, and then a turns those scores into weights. In lesson 4, softmax meant taking escore for each score and dividing by the sum, so that the results add up to 1.

Suppose the pair crowded and averaged has score 0.9, and crowded with itself has score 0.5: my numbers

  1. e0.9 = 2.46 and e0.5 = 1.65. Their sum is 4.11.
  2. Weight of averaged: 2.46 ÷ 4.11 = 0.599, about 0.6.
  3. Weight of crowded itself: 1.65 ÷ 4.11 = 0.401, about 0.4.

This score is really a of two vectors, but not of the tokens' own vectors. The model transforms each token's vector with numbers it has learned to make new vectors, and takes their dot product. Training adjusts exactly these numbers, so that a pair of tokens that matter to each other gets a large score.

The input layout, and one vector to one score

The 2019 paper by Nogueira and Cho turns BERT into a reranker in exactly this way, and the BERT-base 34.7 in Stanford's table comes from this method. The input is a single text: first a special token [CLS], then the query, then a special token [SEP], then the passage, and finally another [SEP]. [SEP] only separates the two parts. The query has at most 64 tokens, and the whole input at most 512. from the paper

The [CLS] vector is also built by attention, and it takes a weighted average over the tokens of both the query and the passage. That is why, at the end, this single vector carries the whole pair. The Aggregator box in the slide's diagram does exactly this: it takes one vector out of all the output vectors, and in Humeau's paper it is the first one. from the paper

Then a small layer turns this vector into one number. In Humeau's paper this layer is a dot product with a vector W that training learns. from the paper This is the Dim Reduction box in the diagram, because it shrinks the whole vector down to one number. Suppose the queue log pair's vector is [0.8, 0.2] and W = [2.0, −1.0]: my numbers

  1. Queue log: 0.8 × 2.0 + 0.2 × (−1.0) = 1.6 − 0.2 = 1.4.
  2. Forum post, whose vector is [0.2, 0.8]: 0.2 × 2.0 + 0.8 × (−1.0) = 0.4 − 0.8 = −0.4.

From score to probability, and the training loss

Nogueira and Cho's reranker gives, instead of a raw score, the probability that the passage is relevant. from the paper A two-class layer like this gives two numbers, one for relevant and one for not relevant, and a softmax turns them into probabilities. Lesson 12 showed that adding the same number to all scores does not change a softmax. So only the difference between the two numbers matters, and the not-relevant number can be set to 0:

  1. The queue log's relevant number is 2.44. e2.44 = 11.47, and e0 = 1.
  2. Probability = 11.47 ÷ (11.47 + 1) = 11.47 ÷ 12.47 = 0.92.
  3. The forum post's number is −0.62: e−0.62 = 0.54, and 0.54 ÷ 1.54 = 0.35.

The office hours page's −0.36 gives 0.41 the same way. These are lesson 6's three scores: 0.92, 0.41 and 0.35. 2.44, −0.36 and −0.62 are my numbers

In training, each question comes with its relevant passages and with non-relevant passages from BM25's top 1,000. The loss is the −ln from lesson 4: −ln(probability) for a relevant passage, and −ln(1 − probability) for a non-relevant one, because its correct answer is not relevant. from the paper

𝓛 = − ∑j ∈ Jpos ln sj − ∑j ∈ Jneg ln(1 − sj)

Jpos is the list of relevant passages, Jneg the list of non-relevant ones, and sj is passage j's probability. The paper writes log, meaning ln. On our two passages:

  1. The queue log is relevant, with s = 0.92: −ln 0.92 = 0.083.
  2. The forum post is not relevant, with s = 0.35: −ln(1 − 0.35) = −ln 0.65 = 0.431.
  3. The sum: 0.083 + 0.431 = 0.514.

The forum post's loss is larger because the model still gives it 0.35, and training pushes its score further down. The paper trained BERT-large with batch size 128 for 100,000 steps, that is, on 12.8 million question-passage pairs, which took about 30 hours. from the paper

Humeau's paper points out one more training difference: a cross-encoder cannot use the of lesson 12. In a bi-encoder, each passage in the batch is encoded once, and every question can use it as a negative. In a cross-encoder, the model runs separately for every question-passage pair. So the paper uses separately supplied negatives, and keeps the batch small because of the extra memory. from the paper

Counting makes the difference between a cross-encoder and a bi-encoder clear. Suppose the corpus has N passages and Q questions arrive per day:

How expensive one model run is shows up in the lower table of Stanford's ColBERT slide. Its last column gives per query, the number of multiplications and additions. Reranking 1,000 passages with the BERT-base cross-encoder takes 97T FLOPs:

  1. T stands for trillion, 1012. Per passage that is 97T ÷ 1,000 = 97 billion FLOPs.
  2. A dot product of two 768-number vectors takes 768 multiplications and 768 additions, which is 1,536 FLOPs.
  3. 97 billion ÷ 1,536 = about 63 million. So one cross-encoder run costs about as much as 63 million dot products.

A bigger model is more accurate but slower still. In Stanford's table, BERT-large reaches an MRR@10 of 36.5, 1.8 above BERT-base. But it takes 32,900 ms for 1,000 passages, 3.07 times as long. Within the 450 ms from step 5, BERT-large could rerank only 450 ÷ 32.9 = 13 passages, against 42 for BERT-base.

The recall ceiling in real numbers

In the upper table of the same slide, BM25's Recall@1000 on MS MARCO is 81.4. comes from lesson 13: the correct passages found in the top k divided by all correct passages, such as 0.5 when 1 of 2 is found. In MS MARCO each question has on average one correct passage. from the paper So 81.4 roughly means that for 81.4 out of 100 questions the correct passage is in BM25's top 1,000, and for 18.6 it is not.

BERT-base reranked exactly these 1,000 BM25 passages, so its Recall@1000 cannot go above 81.4 either. The table's ColBERTL2 (re-rank) row shows this: it also reranks BM25's top 1,000, and its Recall@1000 is exactly 81.4. Reranking took MRR@10 from 16.7 to 34.7, but BM25 fixed the recall ceiling at 81.4.

Hybrid search raises this ceiling, because the merged lists of two retrievers give the correct passage more chances to appear than one list does. 3 points from this lesson

  1. BM25 misses paraphrases, and a dense retriever misses rare literals. Hybrid search merges their lists, but the DPR paper's sum of scores fell behind DPR on NQ and WQ.
  2. RRF adds 1 ÷ (k + rank) from each list. With k = 60, a passage at rank 61 or better in both lists beats rank 1 in a single list, because the condition is r < k + 2. The result of min-max depends on the list's min and max.
  3. In a cross-encoder, attention runs between the query and the passage, so nothing can be built in advance, and one pair costs about as much as 63 million dot products. Reranking took MRR@10 from 16.7 to 34.7, but Recall@1000 stayed at BM25's 81.4.

New terms in this lesson

Paraphrase
The same statement in other words. For example, upload failed and upload keeps failing. BM25 misses it, because it counts shared words.
Literal
Text that has to match exactly, such as the error code E-4012 or the order ID A77-310. A dense retriever can miss it, and BM25 catches it as a rare word.
Hybrid search
Running both a word-based and a dense retriever and merging their lists. For example, making one list from BM25's E1, E3, E2 and dense retrieval's E2, E1, E3.
Reciprocal rank fusion (RRF)
1 ÷ (k + rank) from a passage's rank in each list, summed over all lists, with k = 60. For example, E1: 1 ÷ 61 + 1 ÷ 62 = 0.03252.
Attention
Each token takes a weighted average of the other tokens' vectors as its new vector, and the weights add up to 1. For example, if crowded [0.5, 0.5] gives weight 0.6 to averaged [1.0, 0.0], it becomes [0.8, 0.2].
Cross-encoder
A reranker that joins the query and the passage, feeds them to one model, and gets a direct score for the pair. It runs in full for every passage, for example 10.7 ms per passage with BERT-base.
Reranking
Scoring and sorting a fast retriever's shortlist again with an accurate model. For example, on MS MARCO, MRR@10 goes from 16.7 for BM25 alone to 34.7 after reranking with BERT-base.
Shortlist
The retriever's top few passages, on which the reranker runs. For example, the top 100 of 60,000 passages, which the cross-encoder handles in 1,070 ms.
Min-max normalisation
Mapping each list's scores onto 0 to 1 with (x − min) ÷ (max − min). For example, BM25's 7.2, 3.1 and 1.0 become 1, 0.339 and 0. The result depends on the list's min and max.
[CLS] and [SEP]
Special tokens in BERT's input. [CLS] comes first, and in a cross-encoder its last vector carries the whole pair. [SEP] separates the query from the passage, as in [CLS] query [SEP] passage [SEP].
