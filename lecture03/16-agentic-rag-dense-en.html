Agentic RAG: retrieval as a decision

In agentic RAG, retrieval is no longer a fixed step in a pipeline. At every step an LLM decides whether to retrieve, what to retrieve, and whether what came back is good enough. An LLM working this way is called an agent, and this lesson shows two ways of making these decisions: Self-RAG and CRAG.

The need for it showed up in lesson 11. For the question which office hour is least crowded, BM25 gave the old forum post 2.749 and the queue log 2.473. At K = 1 only the forum post reaches the prompt, and the LLM writes midweek afternoons [P4], where [P4] is that post's ID. This is the wrong answer from lesson 1, now with a citation. The opposite mistake happens too: even for what is 17 × 3? the pipeline searches 60,000 passages.

1Agents: action, observation and the loop

An agent is an LLM that works in a loop. It chooses the next thing to do, that thing gets done, and then it reads the result and chooses again. What the agent chooses to do is called an action, such as searching or writing the answer. A program actually carries out the action, a search engine for example, and that program is called a tool. What the tool returns, and what the agent reads before its next step, is called the observation.

The need for a loop showed up in lesson 6. There, searched twice, and a person had fixed that count in advance. But on the Jed Hoyer question the model made three searches, and 17 × 3 needs none. No fixed count suits both, so the count should come from whoever is reading the result of each search.

Here is a small loop. The user asks in shorthand, OH timings? The retriever is the word overlap from lesson 6, which counts how many query words also appear in a passage. my example loop

StepThe agent's actionObservation
1Search: OH timingsEvery passage scores 0
2Search: CS 329Z office hours scheduleOffice hours page 2, queue log 1
3Answer: Tuesday 4pm, Room 104, or Thursday 9am, Zoom [P2]Loop ends

The first query's words, oh and timings, appear in no passage. In the second query, office and hours both appear in the office hours page, so it scores 2. The queue log has office, but it says hour instead of hours, so it scores 1. The [P2] in the answer is the office hours page's ID.

The second step came from the first step's observation: nothing came back, so the agent rewrote the query. This is the from lesson 6. Lesson 6's Advanced RAG pipeline rewrites every query, which costs an extra LLM call on every query. Each step of the agent also costs an LLM call, but here the rewriting step happened only because the search came back empty.

2Three decisions, and where a pipeline falls short

At every step, an agent that retrieves faces three decisions. First, retrieve or answer directly. Second, which query to send. Third, whether what came back is good enough. All three appeared in the loop of step 1: the agent chose to search, then wrote a new query, then judged the result good enough and answered.

A pipeline makes none of these decisions. It runs the same steps on every question. Below is one question per decision where the pipeline falls short:

DecisionQuestionWhat the pipeline doesWhat an agent can do
1. Retrieve?What is 17 × 3?Searches 60,000 passagesand puts about 2,500 tokens into the prompt0 searches, answers 51 directly
2. Which query?OH timings?Sends that query as is, gets 0 passagesChanges the query when the search comes back empty
3. Good enough?Least crowded, K = 1Sends the forum post aloneThe post is a 2024 opinion, so it searches again

When retrieval becomes an action of the agent, and these three decisions are made at every step, the result is called agentic RAG. Stanford's slide says exactly this:

The when to stop at the top and the third decision at the bottom are the same thing. If the result is good enough, the agent stops and answers, and if it is not, the agent searches again.

The question now is who makes these decisions. This lesson gives two answers. In Self-RAG the model that writes the answer makes them itself, and in CRAG a separate, small model checks the result.

3Self-RAG: decisions as tokens

The most direct option is to let the LLM that writes the answer make the decisions, because it is reading both the question and the passages. The difficulty is that an LLM only writes the . It does not announce decisions separately.

Self-RAG solves this by turning the decisions into tokens as well. It adds some special tokens to the model's , called reflection tokens. The model gets special training, and then it writes these tokens just like any other text. Self-RAG is a 2024 method by Asai and colleagues, and its main tokens are these:

TokenMeaningDecision
RetrieveSearch nowDecision 1
Relevant / IrrelevantWhether the retrieved passage is useful for the questionDecision 3
Supported / PartiallyWhether the passage fully or only partly backs up what the model wroteA second check for decision 3

The paper has a few more tokens, such as No support. A fourth kind gives the whole answer a score from 1 to 5, and it is covered in the dense version.

Now take our question: Which office hour this week is least crowded? Suppose the model wrote Retrieve, and the retriever brought the queue log, the old forum post and the Homework 1 announcement. The model writes the next segment separately with each passage, and adds reflection tokens to each segment. my example and tokens

PassageReflection tokensSegment the model wrote

Old forum postRelevant, PartiallyWednesday afternoon is quietest.

The forum post segment is Partially, because the post says midweek, not Wednesday, and it also says usually. So the Wednesday claim is only half in the passage. The queue log claim is written out in full in the queue log, so that segment is Supported.

So Self-RAG checks each segment on two counts: whether it is useful for the question, and whether the passage backs it up. Stanford's slide shows the paper's own example, and you can now read it:

In step 1 the model writes a first sentence, then Retrieve, and three passages arrive. In step 2 it writes one segment with each passage, and in step 3 the tokens give the order 1 > 3 > 2. The Texas claim is true, but its passage is Irrelevant, so it comes last. Then the model writes Retrieve again and repeats the process.

Self-RAG has a cost. The generator needs special training, so a from an API does not work here. It has to write a separate segment with each passage, which means K generations, like the model of lesson 5. And Supported only says that the claim is in the passage. It does not say that the passage is still true.

4CRAG: a separate evaluator and two thresholds

Most systems are built on a frozen LLM, so decision 3 has to be made by something outside the generator. A first idea is the from lesson 14. But a reranker only changes the order. Suppose the retriever brought only the Homework 1 announcement and the project page, both useless for the crowding question. The reranker still puts one of them on top, and that one goes into the prompt. my example

In CRAG, a small model gives every document a confidence: how right this document is for this question. This model is called the retrieval evaluator. CRAG stands for Corrective RAG, a 2024 method by Yan and colleagues. The confidence has a meaning of its own, so you can set a limit on it in advance, and such a limit is called a threshold.

CRAG keeps two thresholds, an upper one and a lower one. Here the confidence runs from 0 to 1, and the thresholds are 0.6 and 0.2. my scale and numbers The paper's own numbers are in the dense version. Start with the case where the retriever brought a single document, K = 1:

Even on the Correct path the document does not go in whole. CRAG splits it into small pieces called strips. It then checks each strip with the evaluator, drops the useless strips, and joins the rest in order. This is called knowledge refinement. 5Self-RAG and CRAG side by side, and their limits

Now go back to the two questions from the start. On 17 × 3, a well-trained Self-RAG does not write Retrieve, and writes 51 directly. In the paper's own example, too, the model does not search for a prompt that asks for an essay. from the paper CRAG would search here as well, because it searches on every question and only checks the result.

If the forum post arrives alone at K = 1, Self-RAG's Wednesday segment is Partially, and the model can write Retrieve again. CRAG's evaluator gives the forum post 0.4, so CRAG also searches the web. Neither of them passes the forum post on unchecked any more.

Both have limits. A person sets CRAG's thresholds, and the evaluator can make mistakes too. Self-RAG's reflection tokens are also written by the model, so they can be wrong as well. And neither of them learned these decisions by trying things out.

In lesson 17 the model learns these decisions by trying and seeing the result: when to search, which query to write, and when to stop. In a loop, one wrong decision also affects the later steps, which is the subject of lesson 18.

6The maths of Self-RAG: from token probabilities to a segment score

Step 3 had three kinds of tokens, and I gave the order of the segments by looking at the tokens. The paper has four kinds of tokens, and the order comes from a number. Each kind has a few values of its own: from the paper

KindValuesWhat it checks
Retrieveyes, no, continueSearch now, do not search, or keep using the passage retrieved earlier
IsRelrelevant, irrelevantWhether the passage is useful for the question
IsSupfully supported, partially supported, no supportHow far the passage backs up the segment
IsUse5, 4, 3, 2, 1How useful the answer is for the question

The paper calls the last three kinds critique tokens, because they judge what was written. In each kind one value is the best, shown in bold in the table. The Supported of step 3 is fully supported here, and Partially is partially supported.

From a token's probability to a share

At every step the model gives each token in the whole vocabulary a , and together they add up to 1. Self-RAG picks out the tokens of one kind and shares their probabilities among themselves. Suppose that after the queue log segment, relevant has probability 0.54, irrelevant 0.06, and all other tokens together 0.40. my numbers

  1. Add the two IsRel tokens: 0.54 + 0.06 = 0.60.
  2. Divide relevant by that sum: 0.54 ÷ 0.60 = 0.9.

This 0.9 is relevant's share among the IsRel tokens only. The other 0.40 plays no part, so the share always stays between 0 and 1. The paper writes it like this:

sIsRel = p(relevant) ÷ ( p(relevant) + p(irrelevant) )

Here p(relevant) is the probability of the relevant token, 0.54, and the bottom is the sum of both, 0.60. In lesson 4's the share was found the same way: divide one number by the sum of its group.

The retrieval decision: the threshold δ

Decision 1 uses the same kind of share. Self-RAG retrieves when yes's share, between yes and no, is above a threshold. The paper writes this threshold as δ, read "delta":

retrieve if p(yes) ÷ ( p(yes) + p(no) ) > δ

Look at two questions, where p(yes) and p(no) are the probabilities of the Retrieve tokens: my numbers

Each segment's score: a weighted sum

Now the shares of the three critique kinds combine into one number. First each kind's share, by the paper's rules: from the paper

  • IsRel: relevant's share, as computed above.
  • IsSup: fully's share, plus half of partially's share. So partially supported gets half weight.
  • IsUse: the five values get weights. 5 gets 1, 4 gets 0.5, 3 gets 0, 2 gets −0.5, and 1 gets −1. Each value's share is multiplied by its weight, and the products are added.

The IsUse sum is a kind of average. Suppose 5 has share 0.6, 4 has 0.3 and 3 has 0.1. Then sIsUse = 1 × 0.6 + 0.5 × 0.3 + 0 × 0.1 = 0.75. If all the share were on 5 it would be 1, and if all of it were on 1 it would be −1. So sIsUse stays between −1 and 1.

For our three segments, the model gave these shares. Within each group the shares add up to 1: my numbers

The queue log segment's score takes four steps:

  1. sIsRel = 0.9.
  2. sIsSup = 0.8 + 0.5 × 0.15 = 0.875.
  3. sIsUse = 1 × 0.6 + 0.5 × 0.3 + 0 × 0.1 = 0.75.
  4. S = 1.0 × 0.9 + 1.0 × 0.875 + 0.5 × 0.75 = 0.9 + 0.875 + 0.375 = 2.15.

In step 4 the three shares were added with weights. The paper's default weights are 1.0 for IsRel and IsSup, and 0.5 for IsUse. from the paper The formula is exactly these four steps:

S = wIsRel sIsRel + wIsSup sIsSup + wIsUse sIsUse

Here each w is a weight (1.0, 1.0 and 0.5), and each s is that kind's share (0.9, 0.875 and 0.75). The same arithmetic on all three segments:

The paper's full score also adds the segment's own probability to S:

f(yt, d) = p(yt | x, d, y<t) + S

Here x is the question, d the passage, yt the t-th segment, and y<t all the segments written before it. The paper treats each segment as one sentence. p(yt | x, d, y<t) says how likely the model finds this sentence, given the question, the passage and the earlier segments. from the paper

Changing the weights changes the model's behaviour without any new training. Suppose wIsSup = 2. Then the scores are 3.025, 2.025 and 1.175, so the order stays the same, but being backed up counts for more. In the paper, raising the IsSup weight on the ASQA task raised citation precision, meaning more citations really backed up their claims. At the same time a fluency score called MAUVE went down. from the paper, trend read from a graph

Beam search: two unfinished answers at once

The paper does not move forward with just the single best segment at each step. It keeps the B unfinished answers with the highest scores, and extends each of them to the next step. This is called beam search, and B is the width of the beam. In the paper B = 2. from the paper

On our three segments, B = 2 means that the unfinished answers with the queue log segment (2.15) and the forum post segment (1.475) both go on to the next step. The Homework one (0.425) is dropped there. At the end the best complete answer is returned. With B = 1 this would be like the of lesson 1, only with a whole sentence instead of a token.

7Self-RAG's training, and the paper's results

A model can write reflection tokens only if the training data has these tokens in the right places. Adding tokens to every sentence by hand is expensive, so the paper has another model do it. A model that grades what something else wrote is called a critic. Self-RAG's training takes three steps: from the paper

  1. GPT-4 was given an instruction and a few examples for each kind, and asked to write the tokens. This gave 4,000 to 20,000 examples per kind, such as 19,317 for IsRel, 11,181 for IsSup and 3,831 for IsUse.
  2. A critic was trained from Llama 2 7B on these examples, so that from then on the critic writes tokens instead of GPT-4.
  3. The critic added reflection tokens and retrieved passages to 145,619 training examples. Then the generator, Llama 2 7B or 13B, was trained on these examples.

The critic exists only to build training data. Once trained, the generator writes the tokens itself, so no critic is needed when answering.

The generator's training uses the same as lesson 4: −ln of the probability of each next token, with reflection tokens included. For example, if a correct token's probability goes from 0.5 to 0.9, its −ln falls from 0.693 to 0.105. The passage text gets no loss, because the model did not write it. The retriever supplied it. The paper writes the same thing like this:

maxM 𝔼 [ log pM(y, r | x) ]

Here M is the generator, x the question, y the answer, and r its reflection tokens. 𝔼 means the average over all training examples. Making log as large as possible and making −log, the loss, as small as possible are the same thing.

The paper measured how trustworthy the critic is by comparing it with GPT-4's tokens: from the paper

KindAgreement of critic with GPT-4 (%)

When answering, the paper took the top 5 passages from a dense retriever called Contriever. The weights were 1.0, 1.0 and 0.5, δ = 0.2, and the beam width 2. from the paper

8CRAG's real evaluator, thresholds and results

The first figure of the CRAG paper shows the problem clearly. The question is Who was the screenwriter for Death of a Batman?, and the retriever brings a document about Batman (1989 film). The name Hamm appears in it, and the generator answers Hamm, which is wrong. from the paper

CRAG's evaluator is a model called T5-large, with 0.77 billion parameters. Self-RAG's critic is Llama 2 7B, about 9 times larger. The evaluator reads the question and one document together and returns a score between −1 and 1. In training, a correct document had the label 1, and a wrong one −1. from the paper

PopQA has about 14,000 questions, and the paper trained the evaluator on all of them except the 1,399 test questions. The same evaluator was then used on the other three tasks as well. Each question usually brings 10 documents, and the evaluator scores each one separately. from the paper

The −1 to 1 scale

In the easy version I put the confidence on a 0 to 1 scale. The paper's scale runs from −1 to 1, and one simple rule links the two: c = (s + 1) ÷ 2. Here s is the paper's score and c the 0 to 1 confidence. For example, s = −1 gives c = 0, s = 0 gives c = 0.5, and s = 1 gives c = 1. The rule adds 1 to every score and divides by 2, so the order is the same on both scales.

The paper set the thresholds by trying values on each dataset, so they are : from the paper, last column my arithmetic

DatasetUpperLowerOn 0 to 1
PopQA0.59−0.990.795, 0.005
PubHealth, ARC0.5−0.910.75, 0.045
Biography0.95−0.910.975, 0.045

The last column comes from c = (s + 1) ÷ 2. For PubHealth's lower threshold: (−0.91 + 1) ÷ 2 = 0.09 ÷ 2 = 0.045. The lower thresholds sit almost at −1, so Incorrect happens only when every document is almost completely useless.

The numbers for strips and web search

Refinement uses the same evaluator. A long document is split into strips of a few sentences, the evaluator scores each strip, and of the strips above −0.5 the top 5 stay. from the paper For the milestone question, suppose the syllabus strips got 0.8, 0.1 and −0.7. my scores The first two are above −0.5 and stay, and the Week 10 strip at −0.7 is dropped.

For the web, GPT-3.5 Turbo gets a prompt asking for at most three keywords from the question, separated by commas. The paper's example turns What is Henry Feilden's occupation? into the query Henry Feilden, occupation. The Google Search API returns the top 5 pages, and CRAG puts Wikipedia pages first. The same evaluator then runs on the paragraphs of these pages. from the paper

For our question, such a query would look something like office hour, least crowded, this week. my example But this course's queue log is not on the web, so a web search brings back nothing useful here. CRAG still searches, because it acts only on the evaluator's verdict.

The paper also added CRAG on top of Self-RAG, and calls this Self-CRAG. On PopQA it went from Self-RAG's 54.9 to 61.8, 6.9 points ahead. On ARC it went from 67.3 to 67.2, 0.1 point lower. from the paper

When the generator was plain LLaMA2-hf-7b, with no training for reflection tokens, the Self-RAG method fell to 29.0 on PopQA. With the same generator, plain RAG scored 50.5 and CRAG 54.9. This is the point from step 5: Self-RAG needs its own trained generator, and CRAG works with any generator.

How well the evaluator judges was measured on PopQA. The T5 evaluator was right 84.3% of the time. ChatGPT doing the same job reached 58.0%, 62.4% with a step-by-step prompt, and 64.7% with examples. from the paper

In the ablation, removing refinement brought PopQA from 59.8 to 54.2, removing query rewriting to 56.2, and removing the selection among web results to 58.6. Adding web results every time to plain RAG raised accuracy only from 52.8 to 53.8. So the web alone gives 1.0 point, and CRAG's checking adds 6.0 points on top. from the paper

    Show the answer

  2. In the Knowledge Refinement box, what are d1, d2, the strips and kin? Why is strip2 a different colour?

    Show the answer

    d1 and d2 are the documents the retriever brought. 3 points from this lesson

  1. An agent takes an action in a loop, reads the observation, and decides the next action. Every step has three decisions: retrieve or not, which query to send, and whether the result is good enough.
  2. Self-RAG turns the probabilities of each critique kind into shares within that kind, and the weighted sum of the shares is each segment's score. The retrieval decision comes from yes's share and δ = 0.2.
  3. CRAG's T5 evaluator scores from −1 to 1. One document above the upper threshold gives Correct, and all documents below the lower one give Incorrect. On PopQA it lifts RAG from 52.8 to 59.8, which is 7.0 points.

New terms in this lesson

Agent
An LLM that works in a loop: it chooses an action, reads the observation, and decides the next action. For example, when the search for OH timings came back empty, the agent wrote a new query.
Action and tool
What the agent chooses to do, such as searching for OH timings. A tool is the program that does it, such as a search engine.
Observation
The result of an action, which the agent reads before its next step. For example, the result of the first search: every passage scored 0.
Agentic RAG
RAG in which retrieval is an action of the agent, not a fixed step of a pipeline. For example, 0 searches for 17 × 3 and 3 for the Jed Hoyer question.
Self-RAG
The generator itself writes reflection tokens to decide when to retrieve and which segment to keep. For example, Relevant and Partially on the forum post segment.
Reflection tokens
Special tokens added to the vocabulary, which the model writes like any other text. For example, Retrieve, Relevant or Irrelevant, and Supported or Partially.
CRAG
Corrective RAG: an evaluator calls the retrieval Correct, Incorrect or Ambiguous, and refinement, web search or both follow. For example, the forum post at 0.4 is Ambiguous.
Retrieval evaluator
A small model that reads the question and one document and returns a confidence. For example, 0.4 for the forum post at K = 1.
Knowledge refinement
Splitting documents into strips, dropping the useless strips, and joining the rest in order. For example, 2 of the syllabus's 3 strips stay for the milestone question.
Threshold
A limit set in advance, where being above or below it triggers a different action. For example, in CRAG above 0.6 means Correct, and below 0.2 means Incorrect.
Critic
A model that grades what something else wrote or retrieved. For example, in Self-RAG a critic built from Llama 2 7B adds reflection tokens to the training data, and the CRAG slide calls its evaluator a critic.
Segment score (Self-RAG)
The weighted sum of a segment's critique shares: S = 1.0 × sIsRel + 1.0 × sIsSup + 0.5 × sIsUse. For example, the queue log segment's S = 0.9 + 0.875 + 0.5 × 0.75 = 2.15.
Beam search
Moving forward while keeping the B unfinished answers with the highest scores at each step. For example, with B = 2 the queue log (2.15) and forum post (1.475) answers go on, and Homework (0.425) is dropped.
